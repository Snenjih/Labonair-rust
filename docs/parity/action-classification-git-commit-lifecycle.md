# Git Commit Lifecycle Action Classification

**Status:** Static action and workflow classification; native interaction, failure recovery, and paired macOS acceptance pending

**Baseline:** Zed commit `3569541038dd51524b03998ba4d38d253cb54f80`

**Owner:** Git owns repository commit state and the canonical Source Control workflow. Workspace hosts modal/action composition; Editor owns message editing; Agent and language-model providers own generation configuration.

## Evidence boundary

This packet states the pinned commit, amend, message generation, composer, signoff, hook-skip, cancel, and undo workflows and compares current Labonair Git, transport, and Source Control contracts. Static bindings and source establish implementation paths, not native key dispatch, rendered UI, user-visible error recovery, or paired visual parity. Source research and requirements were produced in the same session, so this is independent redevelopment, not separated-room clean-room implementation.

## Owner and workflow contract

| Contract field | Requirement and current Labonair record |
|---|---|
| Commit staged changes | Commit acts when the commit editor has focus. It uses the editor text, a non-empty suggested message when the buffer is exactly empty, or returns focus to the editor when no valid message exists; it rejects unresolved unstaged conflicts and disallows empty commits. If the index has staged changes, those are committed. If not, the panel stages changed tracked entries first; newly created entries are excluded from that path. Success clears the normal draft; failure keeps the pinned draft available. Labonair has staged and tracked commit modes, but its tracked path calls `git add -A`, which also stages untracked files when tracked and untracked changes coexist. The local adapter exposes no matching commit options. |
| Amend the last commit | The first Amend invocation with a HEAD commit enters amend-pending state, preserves the current draft, loads the last commit message into the editor, and serializes the per-repository draft/amend state. A second invocation commits with amend enabled. Turning amend off restores the prior draft. Successful amend exits the pending state. The action only operates while the commit editor has focus. Labonair has a direct Amend checkbox and transport `--amend`, but not the two-step action or original-draft swap behavior. |
| Generate a message | Generation requires a committable state, enabled Agent settings, a configured commit-message model, and an active repository. It uses staged diff when present, otherwise the worktree diff; limits/compresses diff input to 20,000 bytes; uses the configured model temperature; optionally adds project/user agent rules and custom instructions; and streams text into the existing message, preserving it and separating generated text with a newline when non-empty. Provider authentication may run first. Missing prerequisites return without generation; diff/model failures are shown through Workspace error UI. Labonair has no commit-message model route or Generate Commit Message control. |
| Composer size and modal | `ToggleFillCommitEditor` switches the embedded editor between its capped auto-height mode and full-height panel mode. `ExpandCommitEditor` defers to Workspace and toggles a separate commit modal. These are different operations. Labonair has a local height toggle only; its expand control changes a fixed-height panel editor and does not open a modal. |
| Cancel binding discrepancy | Escape is bound to the registered `git::Cancel` action in `GitPanel && CommitEditor`, but no `git::Cancel` handler was found in the pinned source tree. A separate `GitPanel::cancel` listener accepts `menu::Cancel`; it clears marked Changes entries or dispatches `ToggleFocus`, but that is a different action type. Do not attribute that listener behavior to the Escape binding. The actual effect of `git::Cancel` is unresolved and the action description says it cancels the current Git operation. Labonair has no matching action/default binding. |
| Signoff | The unbound Signoff action toggles the commit menu's signoff option. The next commit includes Git's signoff option. The value is serialized with GitPanel state for the workspace. Labonair has no signoff option in its typed commit contract or transport command. |
| Skip hooks | The unbound SkipHooks action toggles the next commit's no-verify option and the menu identifies the corresponding Git command behavior. The choice is transient, is passed into commit options, and resets after a successful commit; it is not persisted with signoff. Labonair has no no-verify commit option or UI. |
| Uncommit last commit | The unbound Workspace action routes to GitPanel. It checks whether HEAD was pushed. If not pushed, it soft-resets to the parent and restores the prior commit message in the composer. If pushed, it asks for confirmation naming the remotes; Cancel leaves history unchanged, while Uncommit proceeds. A failed pushed-state check is statically treated like a declined operation, with no surfaced error in this handler; verify failure feedback at runtime. Labonair has no last-commit undo action, pushed-state check, or soft-reset API. |
| Ownership, contract, and persistence | Labonair's canonical capability is `labonair-git`, with `labonair-git-transport` and `labonair-panel-scm` under the same Git owner. Its current typed contract is `commit(path, message, amend, session_id)` and transport builds `git commit [--amend] -m <message>`. It cannot carry signoff/no-verify options, generate a message, or soft-reset HEAD. No Settings, persistence, event, registry, action, or dependency change is proposed in this packet. |
| Current Labonair routes | Source Control has staged, tracked, and amend modes, commit-message validation, disabled states for missing message/changes, conflicts and an active operation, plus asynchronous error reporting. The tracked mode stages via `git add -A`, including untracked files. The commit input is cleared before the asynchronous mutation completes; no explicit failure restoration path was found and runtime recovery remains pending. Its expand button changes panel height, not modal state. No generated-message, signoff, skip-hooks, Uncommit, or matching Cancel action was found. |

## Action requirements

| Requirement ID | Pinned entry and target | Current Labonair route and gap |
|---|---|---|
| [`ACT-MACOS-git-Commit`](action-requirements.md) | Commit from GitPanel, GitDiff Editor, CommitEditor Editor, or auto-height GitCommit Editor when the composer has focus. macOS uses `cmd-enter`; Linux/Windows use `ctrl-enter`. Commits staged state or stages changed tracked entries when the index is empty. | Source Control commits staged entries or offers a tracked mode; the tracked path uses `git add -A` and can include untracked files. The pinned action, contexts, and bindings are absent. |
| [`ACT-MACOS-git-Amend`](action-requirements.md) | `cmd-shift-enter` on macOS and `ctrl-shift-enter` on Linux/Windows in GitPanel, GitDiff Editor, CommitEditor Editor, and auto-height GitCommit Editor. First invocation loads HEAD's message and enters amend mode; next invocation commits. | Amend checkbox and `--amend` transport support exist; no matching two-step action, key bindings, or prior-draft restoration route. |
| [`ACT-MACOS-git-Cancel`](action-requirements.md) | Escape binds `git::Cancel` in `GitPanel && CommitEditor`, but no handler was found; a separate `menu::Cancel` listener clears marked Changes entries or toggles focus. | No matching action/default binding. Local operation errors are surfaced, but the editor message is cleared before completion and explicit failure restoration was not found. |
| [`ACT-MACOS-git-ExpandCommitEditor`](action-requirements.md) | `shift-escape` in `CommitEditor > Editor`; opens/closes a Workspace-hosted commit modal. | Local expand button only increases the embedded editor height. |
| [`ACT-MACOS-git-ToggleFillCommitEditor`](action-requirements.md) | `alt-shift-escape` in `CommitEditor > Editor`; toggles capped auto-height versus full-height panel editing. | Local fixed-height expansion is pointer-only; pinned modes and binding are absent. |
| [`ACT-MACOS-git-GenerateCommitMessage`](action-requirements.md) | macOS `alt-tab`; Linux/Windows `alt-l`; CommitEditor Editor and auto-height GitCommit Editor contexts. Generates and streams model text under the gates and inputs above. | No matching model/settings integration, action, or UI route. |
| [`ACT-REGISTRY-LINUX-git-Signoff`](registered-actions-unbound.md) | Registered without a default binding; commit menu toggles signoff for future commits and persists the choice with GitPanel state. | No signoff field in Git contract/transport or Source Control menu. |
| [`ACT-REGISTRY-LINUX-git-SkipHooks`](registered-actions-unbound.md) | Registered without a default binding; commit menu toggles no-verify for the next successful commit, then clears it. | No no-verify contract/transport option or menu item. |
| [`ACT-REGISTRY-LINUX-git-Uncommit`](registered-actions-unbound.md) | Registered without a default binding; check pushed state, confirm if already pushed, soft-reset one commit, and restore its message to the composer. | No uncommit action, pushed-state check, confirmation, or soft-reset route. |

## Required user-flow and state acceptance

- Commit staged changes, tracked-only changes, a mix of tracked and untracked changes, only untracked changes, no changes, an empty message, whitespace-only message, unresolved conflicts, and a commit already in progress. Record index/worktree contents and the message after success, failure, and retry.
- Enter Amend with and without an existing draft, edit the loaded message, cancel amend, commit amend, and switch repositories while amend is pending. Verify which draft is restored and what state survives reopening the workspace.
- Generate with Agent disabled, no model, unauthenticated provider, authentication cancellation, staged diff, worktree diff, project rules on/off, existing subject/body text, empty stream, stream error, diff error, and model error. Verify incremental rendering and message retention.
- Use Commit, Amend, Cancel, ExpandCommitEditor, and ToggleFillCommitEditor in every listed context. Record focus, selected Git entries, active tab, modal/panel state, shortcut conflicts, and disabled behavior.
- Toggle Signoff and SkipHooks separately and together. Inspect commit metadata/hooks, switching repositories, canceled/failed commits, successful commit, and restored panel state. Verify Signoff persistence and SkipHooks reset semantics.
- Uncommit an unpushed commit, a pushed commit with Cancel and Uncommit, missing remote state, check failure/offline, reset failure, empty history, and repositories with staged/unstaged changes. Verify remote refs and local HEAD/index/worktree recovery.
- Compare Labonair's tracked mode when staged, tracked-only, and mixed with untracked changes; verify whether a failed async commit restores the cleared message. Compare local expand behavior with the separate modal and confirm the absent generation/options/actions.
- Capture paired native macOS composer, commit menu, amend state, generation loading/error, confirmation, and narrow-layout states. Record exact builds, repository fixture, index/worktree state, focused context, window size, scale, theme, and action result. Verify Linux/Windows key bindings separately.

## Acceptance evidence still required

Static review establishes the six default-bound actions and exact platform contexts, three related registered-unbound actions, commit options and draft behavior, AI-generation gates, pushed-commit warning, and current Labonair Git/transport/Source Control boundaries. It also found that the bound `git::Cancel` action has no source handler; the similarly named GitPanel listener handles `menu::Cancel`, so Escape behavior must be runtime-verified. It does not establish native action dispatch, visible/focus states, message recovery after failures, model-stream behavior, commit metadata/hooks, pushed-ref recovery, or paired visual parity. Labonair has partial commit and amend flows but lacks generated messages, signoff/no-verify options, the modal/action routes, and last-commit undo. Runtime, implementation, and macOS acceptance remain open.
