# Settings Field and Workflow Requirements Register

**Status:** Stable IDs and baseline labels/defaults recorded; field effects, scope validation, ownership routes, and end-to-end acceptance remain open
**Baseline:** Zed commit `3569541038dd51524b03998ba4d38d253cb54f80`
**First acceptance platform:** macOS
**Canonical Labonair values owner:** Settings stores values; each capability owns behavior and persistence

## Inventory scope

This register assigns 488 stable requirements across all 15 static Settings pages, JSON-only values, and dynamic setup surfaces: 384 static field/value rows, 43 per-language typed options, 44 shipped language override profiles, 10 conditional setup pages, and 7 shared Settings flows. The static rows comprise 70 Editor-page controls, 34 other editor-related values, 206 connected page controls, 72 remaining controls, and two Workspace JSON-only values. Three Editor values and two Workspace values have no Settings control and are listed under `Settings JSON only`. A label or default is inventory evidence, not proof that a value is rendered, editable, valid, persisted, or consumed by Labonair.

Two Collaboration Panel controls share the declared path `collaboration_panel.dock`. The second row's packaged default refers to `default_width`, so it has a separate stable ID pending verification of the effective path and behavior. Keep them separate until runtime evidence resolves the conflict.

For every field, verify the user's goal and full flow, canonical owner and typed route, valid values and validation, supported scopes and project trust, reset/inheritance, persistence/reload/migration, live-update or restart, errors/cancellation/recovery, and applicable keyboard, focus, empty, loading, disabled, and narrow-window states. Link paired native evidence and relevant tests. Every row remains `Pending` for acceptance.

Page owners below are routing candidates from the Labonair Settings crosswalk. Exact field owners and public contracts still require confirmation.
